# Лабораторная работа №2

Данный репозиторий содержит намеренно уязвимое веб-приложение и эксплойты для демонстрации уязвимостей.

В рамках данной лабораторной работы реализовано небольшое учебное веб-приложение для создания и просмотра петиций. Пользователь может создать петицию, просмотреть существующие петиции и удалить их.

В проекте представлено две версии приложения:

* `vulnerable_web.py` — версия с намеренно оставленными уязвимостями;
* `web.py` — исправленная и безопасная версия.

Цель работы — ознакомиться с некоторыми уязвимостями из списка OWASP Top 10.

## Ограничения и меры безопасности

Данный проект разработан исключительно в образовательных целях в рамках учебного курса.

* Все демонстрации должны проводиться **только в изолированной локальной среде** с использованием предоставленного приложения и искусственных данных.
* Категорически запрещается открывать уязвимую версию приложения для доступа из интернета или публичных сетей.
* В проекте используются исключительно фиктивные данные. Реальная пользовательская информация и сторонние системы не задействуются.
* Приведённый код не предназначен для использования в production-среде или для предоставления публичного сетевого доступа.
* Запрещается использовать предоставленные эксплойты против сторонних сайтов, сервисов и информационных систем.
* Автор не несёт ответственности за неправомерное использование материалов проекта.

## Исследуемые уязвимости

В проекте рассматриваются три категории уязвимостей из списка OWASP Top 10:2025:

### A01:2025 — Broken Access Control
* **Уязвимая версия:** Функция удаления петиции принимает POST-запрос без проверки полномочий пользователя. Из-за этого любой пользователь может удалить любую петицию, зная лишь её идентификатор.
* **Исправление:** В `web.py` реализована проверка прав, гарантирующая, что удалять петиции может только администратор.

### A04:2025 — Cryptographic Failures
* **Уязвимая версия:** Данные пользователей хранятся в базе данных SQLite в открытом виде. При получении доступа к файлу базы данных злоумышленник сможет прочитать всю конфиденциальную информацию.
* **Исправление:** Данные шифруются с помощью библиотеки `cryptography` (алгоритм Fernet). Скрипт `encrypt_signatures.py` шифрует существующие записи в `secure_database.db`, а ключ хранится отдельно в локальном файле `signature.key`.

### A05:2025 — Injection
* **Уязвимая версия:** В поисковой строке уязвимого приложения пользовательский ввод напрямую подставляется в SQL-запрос, из-за чего пользователь может манипулировать логикой запроса.
* **Исправление:** В защищённой версии используются параметризованные запросы, благодаря чему пользовательский ввод обрабатывается исключительно как данные, а не как часть SQL-кода.

## Структура проекта

```text
Проект/
├── vulnerable_web.py          # Намеренно уязвимая версия (порт 5000)
├── web.py                     # Безопасная версия с исправлениями (порт 5001)
├── database.py                # Создание таблиц и подключение к SQLite
├── crypto_utils.py            # Функции шифрования и расшифрования (Fernet)

├── exploits/                  # Папка со скриптами-эксплойтами
├── patches/                   # Diff-файлы с исправлениями уязвимостей
├── templates/                 # HTML-шаблоны Flask
└── static/                    # Статические файлы (CSS)
```

## Требования

Для запуска требуются Python 3, Flask и cryptography. Установка зависимостей:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```
Первая строка строка создает изолированную среду для конкретного проекта (чтобы не поломать другие проекты на машине), вторая - запускает эту среду, третья - просит установить все модули, описанные в requirements.txt.

## Подготовка

### 1. Создание ключа шифрования

Создайте локальный ключ Fernet (signature.key) и ограничьте к нему доступ:

```bash
python3 -c 'from cryptography.fernet import Fernet; open("signature.key", "wb").write(Fernet.generate_key())'
chmod 600 signature.key
```

### 2. Запуск версий приложения

Приложения автоматически создают базы данных при первом запуске.

#### Запуск уязвимой версии (порт 5000):

```bash
python3 vulnerable_web.py
```

Доступна по адресу: `http://127.0.0.1:5000/`.

#### Защищённая версия (порт 5001):
Задайте переменные окружения перед запуском:

```bash
export ADMIN_PASSWORD='задайте-свой-локальный-пароль'
export FLASK_SECRET_KEY="$(python3 -c 'import secrets; print(secrets.token_hex(32))')"
python3 web.py
```

Доступна по адресу: http://127.0.0.1:5001/ (вход для администратора: /admin/login).

### 3. Шифрование базы данных

После создания базы защищённой версии выполните скрипт шифрования:

```bash
python3 encrypt_signatures.py
```

## Проверка эксплоитов

### A05 - SQL Injection

Запустите уязвимую версию на порту 5000 и выполните:

```bash
python3 exploits/sql_injection_exploit.py
```

### A01 - Broken Access Control

- Для уязвимой версии: запустите приложение и выполните:

```bash
python3 exploits/bac_exploit.py
```

- Для защищенной версии: авторизуйтесь под администратором в браузере (http://127.0.0.1:5001/admin/login), измените порт в скрипте эксплойта на 5001 и запустите его.

### A04 - Cryptographic Failures
Сравните содержимое таблиц в базах данных:

- database.db — открытый текст;
- secure_database.db — зашифрованные данные.
